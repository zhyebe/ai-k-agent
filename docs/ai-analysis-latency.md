# AI 分析耗时优化

## 范围

v0.3.89 删除同一请求内重复的入场提示，以及历史 user 消息中重复携带的 decision。每轮历史仍保留行情和对应 assistant 决策，最近 8 轮全部保留；当前市场、全部已审核知识库、持仓、委托和 previousAnalysis 不删减。

快速分析采用简短结论：摘要最多 120 个汉字，各解释尽量一短句。参考 [Caveman Micro](https://github.com/kuba-guzik/caveman-micro) 的精简表达思路，保留不确定性、完整 JSON 和交易字段，不采用原版的“取消保留意见”规则，也不加入新的长篇知识库。逐仓 exit_plans、逐委托 order_assessments 和逐品种 board_assessments 不受摘要条数上限影响。

保留 StepFun high 和原输出额度、DeepSeek 快速配置及其他协议。完整性校验和单次补全仍在，不能把截断 JSON 当成可执行动作。原始 observedAt、决策有效期和现有交易执行逻辑保持不变。

## 模型对照记录（2026-10-17）

使用现有 StepFun step-5-preview / Anthropic 接口、high 档，以同一份隔离合成数据按“原版、优化版、优化版、原版”顺序请求。仅调用分析模块，不创建任务、提交订单或修改账户。每次对照设置 180 秒测量超时；生产超时配置未调整。

同数据输入 token 减少约 23.4%，已返回的决策均完整覆盖持仓和委托。但第二次优化请求超时，且原版第二次命中缓存，因此这四次结果不能证明稳定耗时改善。输出 token 含推理，不等于可见说明长度。后续需在正常监控中积累同模型、同规模指标；本次不宣称解决了全部延迟或提高了交易预测准确率。

## 运行期指标

`decision.modelDiagnostics` 新增以下数字字段，随任务保存；发生模型补全时，每次请求的指标保留在 `attempts`：

- `requestBytes`：最终成功接口的 UTF-8 请求体字节，不包含请求头。
- `responseDurationMs`：请求开始到读取、解析完整响应的耗时，包含接口路径协商；不是首 token 耗时。
- `providerAttempts`：本次请求尝试的接口数量，与补全请求次数区分。
- `usage`：供应商返回的 inputTokens、outputTokens、cachedInputTokens、cacheCreationInputTokens、reasoningTokens；缺失或无效字段不伪造为零。

Anthropic 输入 token 包含新输入与缓存读写；Gemini 输出 token 合计回答与推理。只保存已知数字，不保存原始响应、思考正文或凭证。比较实际延迟时应同时看相同模型、请求规模、缓存命中和补全次数；小样本不能证明稳定提速或预测准确率。
