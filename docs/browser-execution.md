# 浏览器执行与 Windows 后台回归

## v1.0.8：入场弹框被误取消

- 真实网页把整块订立表单放在 `li.left` 内，下单按钮使用 `input[type=button]`。最终复核曾把该按钮父级的“买价/买量”或“卖价/卖量”当成额外字段，返回 `ENTRY_FORM_CHANGED` 后主动点击取消。先前夹具没有外层 `li`，遗漏该结构；新增多空案例在修复前均能复现。
- 用户要求 AI 明确买卖后直接下单，因此删除整段最终字段、空仓、深度与时效复核，以及分析后和提交前的重复账户采集；不再因此改为 HOLD 或点击取消。共享网页夹具保留真实外层表单结构，浏览器与桌面安装包检查都使用它。
- 市价更新只刷新可读的真实盘口价格，不因深度不足、报价年龄或账户表格状态否决本次 AI 动作；没有可读盘口时保留本次明确的 AI 价格，不补造数值。限价保留指定价格。
- 确认动作核对控件实际文案，AI 选中的取消或关闭按钮不能作为确认。保存实际确认/取消按钮文案与具体失败原因，任务直接显示执行失败原因。停止开关与同一动作防重复保留；提交结果未知时仍按当前委托和持仓对账，不重复提交。

## v0.3.122：控件重绘与并发取消

- macOS v0.3.121 排查复现：确认按钮在扫描后被网页重绘，临时控件标记随旧节点消失；`locator.isDisabled()` 仍等待旧标记，默认可等待 30 秒后报 `TRADE_SUBMIT_FAILED`。确认按钮状态与点击前标记检查改为即时读取当前节点；节点消失则在原弹窗内重新扫描并再次复核报价，不重放已发出的点击。
- 完整行情采集的网络等待已释放页面队列，但旧取消处理仍会关闭整个浏览器；可打断此时正在执行的入场、离场。取消关闭仅绑定持有页面队列的阶段，等待网络或排队的采集过期不能关闭其他操作；窗口恢复阶段也纳入取消处理，关闭完成后才释放队列。
- 当前委托、持仓采集也需要切换标签和分页，现对每个采集页面阶段恢复最小化、隐藏窗口；网络等待后再次采集也重新检查。无页面切换的控件扫描保留窗口状态。
- 回归覆盖扫描后重绘、报价复核期间重绘，以及采集超时与交易并行。安装包测试在最小化、隐藏窗口中先读取当前委托和持仓，再分别重绘多空入场、离场确认按钮，核实每个动作只提交一次。

以下为早期版本的排查记录。

AI 作出交易决策后，浏览器仍须完成字段填写、目标行定位、点击、弹窗确认及结果核实。v0.3.110 修复这段执行链，不修改收益目标和止损规则。

## 故障证据

- 2026-10-20 的持久化任务保留一次入场失败：`The operation was aborted due to timeout`，耗时约 22.8 秒。历史动作输出未持久化，无法据此统计全部失败原因。
- 标准表单和持仓行存在时，原执行仍重复请求浏览器定位 AI。隔离测试让该服务返回 HTTP 503，能复现多空入场及转让失败。
- 重新采集网站公开脚本 `chunk-7773df40.7791d9fa.js`：持仓行使用转让控件，弹窗价格在打开后 200 ms 初始化；入场还有独立的确认步骤。
- 原 AI 弹窗分支直接点击确认，可能绕过限价填写。持仓行按索引保存，重排后可能指向另一笔持仓。
- Windows 安装包实测：最小化窗口中，`scrollIntoViewIfNeeded` 等待稳定帧超时；仅禁用后台节流不足以恢复渲染。v0.3.109 候选被发布检查拦截，未发布。

## 执行约束

- 当前页面存在已识别的语义控件时，直接填写并执行 AI 已确定的方向、价格和数量，不额外等待模型。
- 无法识别改版控件时，向 AI 提供新快照。模型返回期间若控件被重绘，仅在新快照中存在唯一、语义一致且目标持仓匹配的控件时重新定位；歧义或目标不符则拒绝。
- 持仓行按完整单号绑定；确认按钮必须位于当前交易弹窗。所有确认共用价格填写与持仓、报价、费用复核，不延长离场 guard 的有效期。
- 点击后发生异常，结果标记为待核实，交由持仓对账，避免直接重放。任务保存最近执行的阶段、错误码和耗时。
- 交易窗口禁用后台节流和遮挡降频；执行前自动恢复最小化、隐藏的交易窗口，让 Playwright 在可渲染的窗口中正常操作，保留点击检查。只读控件状态检查不等待已卸载节点 30 秒。

## 回归

`tests/browser-trade-controls.test.mjs` 覆盖浏览器定位 AI 不可用、即时弹窗限价、页面改版、错误持仓拒绝、重排及重绘后的精确定位，另保留多空最终报价、成本、数量、冻结和过期检查。

`npm run test:desktop-browser` 使用本地模拟网页，通过实际 Electron runtime 测试可见窗口及从最小化、隐藏状态恢复后的多空入场和有 guard 的多空离场，并断言窗口已恢复。发布流程在 Windows x64 和 macOS universal 安装包内运行同一验证；Windows 另外运行浏览器执行、登录和桥接回归。测试不提交真实交易。
