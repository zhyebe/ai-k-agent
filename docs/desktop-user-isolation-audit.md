# 桌面端用户数据隔离审计

审计日期：2026-10-13。范围：Electron、本地存储、前端请求层、用户 API、持久化与 AI 上下文。结论：个人业务数据按登录用户隔离；已修复退出后旧请求污染后续登录界面的问题，并补齐退出时的任务停止、连接关闭与会话清理。产品只有退出登录，没有切换账号功能；审计场景为 A 退出后 B 在同一客户端登录。Skills/经验已按本次要求改为全员共享。

本次变更：

- Skills 列表、检索、统计及 AI 经验选择取消用户读取过滤。草稿可读，但不会作为 AI 经验传输。
- 保留创建者审核/删除权限；`owned` 按当前用户与创建者是否一致计算。
- 删除账号保留共享经验及索引；MySQL 启动迁移移除历史 `skills.owner_user_id` 对用户的级联删除外键，MongoDB 与内存清理也保留知识。
- `ownerUserId` 仅用于创建者管理权限，不再控制知识读取或账号删除时的清理。创建者删除后，该知识继续可读、可用于 AI；现有 API 不支持其他用户接管其管理权限。
- 共享知识超过上下文预算时返回 `AI_KNOWLEDGE_TOO_LARGE`，不会静默截断原文或遗漏部分经验。
- 更新桌面知识库、管理员删除账号提示和 README。

已修复的退出问题：

1. **[P1] 迟到写响应重新填入旧用户数据。** 原实现退出只清空部分 React 状态，业务回调仍可将 A 的任务写入 B 的工作区。已在真实 React 页面、隔离 Chrome 上下文和模拟 API 复现。现在退出立即卸载整个会话组件，清空工作区、表单、弹窗、选择、输出、提示和忙碌锁；请求层同时取消旧请求并校验会话代次、服务地址和 token。页面回归故意让旧 fetch 忽略取消，B 登录后再释放 A 的响应，确认 A 的任务、Provider 和迟到提示均不会出现。
2. **[P2] 写请求去重跨会话/服务复用。** 原去重键只有方法、路径和请求体，B 的相同提交可能复用 A 的 Promise。现在键包含服务地址与认证身份；退出或变更会话时清空去重表和请求计数。API 模块回归验证 B 的提交独立发送，旧响应返回 `SESSION_ENDED`，旧请求结束也不会扣减新会话的计数；同一会话内仍正常去重。
3. **[P1] 退出只撤销 token，任务继续运行。** 现在服务端立即使当前 token 失效，对该用户全部任务执行停止锁定，清除待执行动作、定时器和后续调度；关闭其 SSE、WS 与桌面 AI 连接，等待停止状态和会话撤销持久化完成。双用户集成验证 A 的两个任务停止、B 的任务继续运行，A 的未完成 AI 调用被中断。退出停止自动运行，不替用户平仓或撤销已提交至目标站点的订单。
4. **桌面断开 IPC 提前返回。** 原 IPC 调用浏览器清理后立即返回成功。现在等待清理完成，关闭失败会传回界面；行情缓存、浏览器调用队列和交易确认记录在退出时清空。登录界面在服务端退出和桌面清理完成后才恢复；失败明确显示“服务端任务停止未确认”或桌面关闭失败。
5. **打开交易页时断线丢失目标登录态。** `openMarketBrowser` 原来未纳入只读调用的断线处理，连接中断或重连时会关闭浏览器，导致目标站 `sessionStorage` 中的登录信息丢失。现已纳入：旧调用仍中止，交易页面保留供重连后使用；退出仍完整关闭运行环境，交易调用中止后不会重放。新增两个回归测试在修复前均能复现误关闭，修复后通过。

退出清空的是当前会话的界面、请求与运行环境。已持久化的个人 Provider、任务配置、凭据和按用户隔离的浏览器档案保留供下次登录；共享 Skills 与经验保留。退出不是删除账号，设备级服务地址和更新配置也保留。
